# 02 — Надёжное ядро регистрации и начислений

**Требования:** R09, R12, R14, R15, R17, R18, R19, R20, R24, R32i, R33i, R34i
**Blocked by:** 01
**Зона:** `site/src/lib/club/` · `site/tests/club/`
**Волна:** 2
**Status:** ready

## Что должно заработать

Появляется изолированный Club-модуль со state machine кандидата, стабильным referral code, Syrve adapter boundary и идемпотентным ledger. Его можно проверить без live-секретов: повторная регистрация и повтор события чека дают тот же результат, PII не попадает в логи, а недоступная внешняя интеграция возвращает честный `not_ready`.

## Из брифа, дословно

> «создание партнера в сервере»
> «сервер начисляет партнеру, который его привел, бонусные баллы»
> «бонусный счет в виде злотых»

## Разделы спецификации

Модель данных; Контракты Syrve; Наблюдаемость и безопасность; Границы и швы.

## Критерии приёмки

- [ ] Registration state machine покрывает pending, active, rejected и suspended
- [ ] Один phone identity и один referral code не дублируются при повторе
- [ ] Ledger гарантирует одно начисление 5 PLN на один закрытый чек
- [ ] Syrve adapter имеет fake и explicit not-ready implementation
- [ ] Логи и тестовые данные не содержат телефона, card number или secret values
- [ ] Unit tests покрывают happy path, повтор, сбой внешнего сервиса и reversal boundary
