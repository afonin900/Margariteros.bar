3. **Есть шестая действующая часть — бронирование.** Открытая [#44](https://github.com/afonin900/Margariteros.bar/issues/44) связывает booking-service, аналитику, сайт и R Club. В `/Users/afonin900/Github/afonin-hq/portfolio/projects.yaml` booking-service пока не перечислен; у записи также два `last_verified_at`. Это отдельное исправление карты Штаба, не повод перемещать сам Штаб.
4. **Старые `site/` и `content/` нельзя считать лишними по имени.** В `Margariteros.bar/site/` остаются 445 отслеживаемых файлов; отдельный сайт имеет своё происхождение в `PROVENANCE.md`. Различия и уникальные материалы требуют отдельного сравнения. На этапе раскладки ничего из старого репозитория не удаляется.
5. **Историю R Club нельзя механически слить с историей сайта.** Разделение сохранило самостоятельное происхождение RefRef. Для общей папки слияние вообще не требуется.
6. **Перенос затрагивает местные ссылки.** Служебные данные Content Factory и Graphify содержат абсолютные пути; выборочная проверка отслеживаемых настроек не заменяет проверку игнорируемых местных файлов, настроек редактора и заданий. Старый граф из 558 узлов не описывает новое разделение и не является текущей картой проекта.
7. **Закрытый статус задачи не равен доказательству каждой проверки.** У #39 тело всё ещё содержит незакрытые пункты. Настоящий аудит выпусков потребует прочитать комментарии и проверить серверы отдельно; он не нужен для подготовки этой раскладки.

## Порядок выполнения

### 1. Подготовить сохранение и остановить конкурирующие изменения

- Повторно снять ветку, полный HEAD, статус, удалённый источник и список рабочих копий каждого репозитория.

- Сделать защищённую локальную резервную копию с `.git`, игнорируемыми и неотслеживаемыми файлами. Git bundle или patch по отдельности не сохранят всё. Секретные файлы не выводить, не помещать в отчёт или Git.
- Подготовить перечень файлов и контрольные суммы в защищённом месте; обеспечить место для копии. Отдельно сохранить обе рабочие копии Codex.

Приёмка: можно восстановить весь checkout, включая новый материал DJ Kike и местные настройки; исходное состояние описано без раскрытия секретов.

### 2. Сделать общий вход

- Создать родительскую папку и короткий README с назначением каждой части и ссылками на её GitHub-задачи.
- Добавить файл рабочего пространства редактора с относительными путями к семи папкам.
- Не выполнять `git init` в родительской папке. Общие инструменты Content Factory, Штаб и инфраструктура остаются на своих местах.

### 3. Перенести одну небольшую часть и проверить способ

- Начать с чистого `margariteros-ads`.
- Переместить каталог целиком с `.git`, сохранив разрешения и ссылки. Не заменять это новым clone, который пропустит местные файлы.
- Проверить HEAD, ветку, origin, полный статус и контрольные суммы; открыть папку из общего рабочего пространства.
- Исправить обнаруженные рабочие ссылки. Исторические отчёты не переписывать массовой заменой.

Приёмка: состояние Git и файлы совпадают с исходными, местные команды находят проект. Никаких команд публикации рекламы.

### 4. Перенести оставшиеся части по одной

Порядок: analytics → booking-service → r-club → site → content → Margariteros.bar. После каждой части повторять проверку сохранности; при отличиях остановиться и разобраться до следующего переноса. Состояние неполной истории R Club сохраняется; загрузка полной истории не обязательна для перемещения.

Старый `Margariteros.bar` переносится последним из-за связанных рабочих копий. Оставить служебные копии в `.codex/worktrees/`, восстановить их связь с перемещённым основным репозиторием штатным `git worktree repair`, затем проверить Git в основном checkout и обеих копиях. Обычный перенос каталога без восстановления связи недостаточен.

Основные семь папок окажутся в одном месте; служебные копии Codex останутся снаружи. Если нужно буквально перенести и их, это дополнительный этап через `git worktree move` после проверки поддержки со стороны Codex, а не обычное перетаскивание папок.

Приёмка: все семь папок открываются из одного места; HEAD и исходные несохранённые изменения сохранены; обе служебные копии доступны; проверки проходят либо их прежние ошибки отдельно объяснены. GitHub-адреса и серверные настройки не изменились.

## Откат и граница завершения

При проблеме вернуть конкретный каталог по таблице старых и новых путей, восстановить местные настройки и связи рабочих копий, проверить исходные HEAD и статусы. Резервную копию сохранять до приёмки; её удаление требует отдельного разрешения.

Удаление дублей, архивирование старого репозитория, слияние веток, изменение размещения сайта, публикации и изменение внешних аккаунтов не входят в перенос. Следующая работа после раскладки — отдельное сравнение старых и новых материалов с перечнем уникальных файлов; только затем можно предложить уборку.
