## Зачем этот файл

Это единая исходная точка для постоянной рекламы Margariteros: что уже измеряется, на что реально были потрачены деньги, что нельзя ломать и какой порядок изменений приведёт к измеримым броням и визитам, а не только к кликам.

## Короткий вывод

1. **Google Ads сейчас оптимизируется в основном на действия в Google Maps, а не на подтверждённые брони.** Performance Max ведёт прямо в Google Maps и получает почти весь объём оттуда.
2. **Meta в июле и августе покупала трафик и переходы в Instagram, не доказанные брони.** В июле большая часть расхода пришлась на две старые промо-кампании; в августе были только разовые объявления мероприятий.
3. **Meta Pixel уже работает в ChoiceQR; второй Pixel через GTM ставить нельзя.** GTM может добавлять только отсутствующие дополнительные события поверх существующего Pixel.
4. **Полная серверная цепочка пока не доказана.** В ChoiceQR включён CAPI, но в Meta Events Manager ещё надо проверить серверные события, их дублирование и качество сопоставления.
5. **Рекламной постоянной посадочной страницы пока нет.** Для Google и Meta нужна отдельная страница про мексиканскую кухню, события и бронирование, без алкогольного ассортимента, формулировок и визуалов.

## Что реально работает сейчас

### Сайт, согласие и Google

- Основной сайт: `https://margariteros.bar`.
- QR-адрес ChoiceQR — только промежуточный переход; не считать его основным сайтом.
- GTM web: `GTM-T5F4VVGF`; GA4: `G-ZYB0MZ1CSR`.
- ChoiceQR не грузит GTM и GA4 при выборе посетителем «только необходимые». После `Accept All` загрузка разрешена.
- В истории GTM есть опубликованная версия 8 `Contact click measurement`. При следующей правке сначала сверить фактическую опубликованную версию: доступное рабочее пространство в API выглядит старее и содержит только два тега. Нельзя записывать новые изменения поверх этого расхождения.

### Meta Pixel и CAPI

Pixel: `2116623422287913`, название `Margariteros pixel`.

Подтверждено live:

- Pixel вставляет сам ChoiceQR, не GTM.
- После `Accept All` ChoiceQR вызывает `fbq('init', pixel_id)` и один `PageView`.
- На прямой загрузке `/booking` и на SPA-переходе Home → Booking зафиксирован ровно один `PageView`.
- При «только необходимые» нет запросов к Meta, GTM или GA4.
- В конфигурации ChoiceQR включены `fbCAPI` и measurement.

В коде ChoiceQR предусмотрены: `ViewContent`, `AddToCart`, `InitiateCheckout`, `AddPaymentInfo`, `Purchase`, `CompleteRegistration` и `Schedule` после успешной брони. В этом срезе фактически доказан только `PageView`: проверка `Schedule` потребовала бы настоящей брони.

Ограничение: включённый CAPI ещё не доказывает, что Meta принимает события сервера. У browser-события `Schedule` не подтверждён общий `event_id`; поэтому его browser/server-дедупликация не доказана.

**Правило:** не удалять номер Pixel в ChoiceQR и не добавлять Meta base tag, `PageView`, `Schedule` или `Purchase` в GTM, пока отдельно не подтверждён безопасный перенос всей связки ChoiceQR Pixel + CAPI.

## Постоянная рекламная стратегия

### Цель

Не «дешёвый клик», а последовательность:

`переход на посадочную страницу → начало бронирования → подтверждённая бронь → фактический визит`.

Пока подтверждённая бронь не передаётся, нельзя давать алгоритмам Google/Meta оптимизироваться по ней.

### Общая посадочная страница для рекламы

Нужна отдельная публичная страница на `margariteros.bar`, например `/warsaw-mexican-food-events`.

Содержание:

- мексиканская кухня и тако;
- музыка, вечерние события и атмосфера;
- адрес, часы, карта и бронирование;
- меню еды;
- польская и английская версии; испанская — только после готового качественного перевода.

На рекламной странице не размещать алкогольное меню, названия алкоголя, акции на алкоголь и алкогольные визуалы. Это не обход правил, а отдельное правдивое предложение кухни, событий и бронирования. Ссылка на обычное полное меню может оставаться отдельной пользовательской навигацией, но не должна быть главным рекламным маршрутом.

### Google Ads

1. Оставить Search как управляемую кампанию намерения гостя.
2. Сделать отдельную англоязычную группу объявлений для физически находящихся в Варшаве гостей; настройки местоположения — присутствие, а не интерес к городу.
3. Испанский запускать только с готовыми испанскими объявлениями и посадочной страницей.
4. Добавить UTM к каждому рекламному маршруту на `margariteros.bar`.
5. PMax не считать кампанией бронирований. Отдельно принять решение: либо оставить её с жёстким лимитом как кампанию маршрутов в Maps, либо остановить после появления нормальной конверсии брони.

### Meta Ads

1. Не возобновлять старые `Promo Traffic` как постоянную рекламу.
2. Отдельная постоянная кампания должна вести на рекламную посадочную страницу с UTM, а не только в Instagram-профиль.
3. Пока не подтверждён `Schedule`, оптимизировать только на прозрачный ранний сигнал: просмотр посадочной страницы или клики, и не выдавать это за брони.
4. После проверки `Schedule` в Events Manager — тестировать оптимизацию на него. После появления подтверждённой брони — оптимизировать только на подтверждённое событие.
5. Разовые кампании событий оставить отдельной линией бюджета и сравнивать по своему UTM, а не смешивать с постоянной рекламой.

## Что должно отслеживаться

| Событие | Источник | Статус | Для чего |
|---|---|---|---|
| PageView | ChoiceQR Meta Pixel | доказано | базовый охват/ремаркетинг |
| просмотр меню и страницы брони | GA4/GTM | настроить и проверить | воронка сайта |
| клик телефон/маршрут/e-mail | GA4/GTM; Meta только при отсутствии дубля | Google часть есть в версии 8; Meta не добавлен | микроконверсии, не основная оптимизация |
| успешная бронь `Schedule` | ChoiceQR | кодом предусмотрен, live не доказан | кандидaт на следующую оптимизацию |
| подтверждённая бронь | отдельный conversion bridge | не подключено | настоящая рекламная конверсия |
| фактический визит | Serve → conversion bridge | не подключено | конечный бизнес-результат |

Для будущих серверных событий нужна отдельная связка ChoiceQR/Serve, которая хранит дедупликацию. Ключи: `choiceqr:{booking_guid}:confirmed:v1` и `serve:{table_close_id}:completed:v1`. Не посылать в GA4 сырые имя, телефон или e-mail.

## Контейнеры и следующий порядок работ

| Компонент | Состояние | Следующее действие |
|---|---|---|
| ChoiceQR Pixel/CAPI | browser Pixel доказан; CAPI не подтверждён в Meta | аудит Events Manager: browser/server, Diagnostics, event match quality, дубли |
| Web GTM | установлен; перед правками нужно сверить опубликованную версию и workspace | отдельный чистый workspace для недублирующих Meta-событий |
| Server GTM | не является подтверждённым маршрутом прод-трафика | не направлять трафик, пока не появится клиент, GA4 forwarding и проверка |
| Conversion bridge | отсутствует | после подтверждения API ChoiceQR/Serve реализовать бронь и визит с идемпотентностью |
| Google/Meta кампании | читаются; все проверенные Meta кампании остановлены | сначала посадочная страница + UTM + измерение, затем новые кампании |

## Ближайший порядок

1. В Meta Events Manager снять фактическую таблицу событий за 28 дней и доказать или опровергнуть CAPI/Schedule/dedup.
2. Подготовить и согласовать рекламную посадочную страницу без алкогольного ассортимента.
3. Исправить состояние GTM workspace и добавить только недублирующие события.
4. Согласовать целевое событие постоянной рекламы: сначала прозрачный ранний сигнал, затем подтверждённая бронь.
5. Создать новые Google Search и Meta постоянные кампании только после шагов 1–4; старые кампании не переиспользовать.

## Не делать без отдельного решения

- не включать старые промо-кампании;
- не менять бюджет, ставки или отправлять объявления;
- не добавлять второй базовый Meta Pixel в GTM;
- не удалять Pixel ID или CAPI из ChoiceQR;
- не направлять трафик на server GTM до готовой цепочки;
- не считать клик, маршрут или CTA подтверждённой бронью.
