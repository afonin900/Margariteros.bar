# Аналитика

Здесь описывается, что именно измеряем, откуда берутся данные и что можно
считать доказанным. Это не место для включения трекинга без согласования.

## Что хранить

- `tracking-plan/` — события, UTM-правила, параметры кампаний и проверяемые
  определения метрик.
- `choiceqr/` — возможности и ограничения ChoiceQR: GA/GTM, API, webhooks,
  Measurement Protocol и доступные события.
- `architecture/` — схема будущего first-party переходника, server-side GTM,
  consent и границы данных.
- `reporting/` — структура отчётов, источники и ограничения интерпретации.
- `advertising/` — реклама Google Ads и Meta: требования к событиям,
  атрибуции, диагностике и approval gates.

## Главная граница

Клик в ChoiceQR не равен брони, пока сама платформа не отдаёт подтверждённое
событие. Реальные доступы, домен, cookies/consent и запуск production-tracking
требуют отдельного одобрения владельца.

Web и server GTM уже существуют; не объявлять server GTM доказанным маршрутом
прод-трафика, пока конкретная проверка не подтверждена. Новые сервисы и
изменения production-конфигурации требуют отдельного решения владельца.

## Как начинать аналитическую задачу

1. Прочитать `../docs/growth-os/JUNGLE-MCP-ACCESS.md` и проверить Jungle MCP.
2. GTM и Google Ads сначала инвентаризировать через MCP; не искать токены и не открывать Chrome без необходимости.
3. Браузер использовать только для поведения ChoiceQR, GTM/Server Preview, Network и GA4 DebugView.
4. Последнее подтверждённое состояние — `../docs/growth-os/HANDOFF-2026-08-20-choiceqr-syrve-analytics.md`.
